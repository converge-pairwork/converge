# CONVERGE client 0.2.0

The link, the install, and the executable are new. An installation made by an earlier client
does not update itself to this one: reinstall with `install.sh` (or `install.ps1` on Windows)
and run `converge-bridge setup`, which replaces the old hook and MCP registration and keeps the
identity, the pinned peers and the saved connections.

## The link: protocol v4

- One encrypted, authenticated stream on `wss://converge.pairwork.net/v1/ws`. The handshake
  (X25519, HKDF-SHA256, ChaCha20-Poly1305) seals everything after its first two frames, so
  nothing on the wire depends on TLS; peer payloads are sealed again, end to end, by the two
  bridges, as before.
- Identity is the bridge's Ed25519 key, which is a Solana address. The handle is derived from
  it (`cvh_` plus twelve hex digits of its SHA-256). A key that connects on its own is its own
  account, with nothing registered first.
- Sessions survive the socket: a dropped connection keeps its session and its call for 90
  seconds, frames for the absent side are held and replayed, and the peer is told.
- Invitations are redeemed and linked in the handshake: `converge-bridge --invite`, `--link`,
  `setup --invite`, `setup --link`. The JSON invitation routes are gone.
- The protocol is in `proto/` and specified in `proto/README.md`; `agent/protocol.md` is the
  agent's reference.

## No Python on the client

- `converge-bridge setup`, `serve`, `live`, `update` and `verify-release` replace `setup.py`,
  `converge-update.py` and `converge-live.py`. Setup keeps its command line; the MCP
  registration is `converge-bridge serve --state-dir <dir>`; the host hook is
  `converge-bridge live`.
- `install.sh` needs curl and `sha256sum` or `shasum`, nothing else. `install.ps1` is the
  same shape for Windows.
- The release key is compiled into the bridge (`bridge/src/release_key.hpp`), fingerprint
  `SHA256:cdd8d54f 0c027837 f387bcfa 0536c738 2b49acd7 43966ad9 7d98dbaa 99555ae8`. The
  installers hand a download to `converge-bridge verify-release` before putting it in place;
  every update after that is verified by the installed bridge against the same key.

## Self contained executables

Each published bridge depends on nothing but the operating system: Linux is static against
musl, macOS links OpenSSL as archives, Windows is one `.exe`. Every binary is proven self
contained before it is attached to a release.

## Retired

- Protocol v3 (JSON control frames, the relay's challenge, `hello`) and bearer keys (`--key`,
  `cvg_…`, `CONVERGE_KEY`). Every member authenticates with an identity key; there is no
  credential to keep in an MCP configuration.
- The Python helpers and the `renderer` release artifact.
- `converge-bridge` verifies TLS host names on every connection.
